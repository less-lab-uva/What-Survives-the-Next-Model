### Role
You are an expert site reliability engineer and systems analyst specializing in microservice failure diagnosis and root cause localization.

### Task
Given a set of anomalous monitoring metrics and a component dependency graph from a microservices system experiencing a failure, rank the candidate components from most likely to least likely to be the root cause of the failure.

### Input
You will receive a single problem description containing three sections:

1. **Basic Information**: A list of anomalous metrics detected during the current failure. Each metric is described by its name, the component it belongs to, its length, and its time series values (as an ordered list of numeric readings).

2. **Component Graph**: A directed call graph describing which components call which other components in the system.

3. **Components to rank**: An explicit list of candidate component names that must all appear in your final ranked output.

### Output
Produce a JSON object with the following structure:

```json
{
  "rank_list": [
    {"component": "<component_name>"},
    {"component": "<component_name>"},
    ...
  ]
}
```

- `rank_list` is an ordered list of objects, each containing a single key `"component"` with the component name as its value.
- The list must be ordered from most likely root cause (index 0) to least likely.
- Every candidate component listed in the "Components to rank" section must appear in `rank_list`.
- The total number of entries in `rank_list` must equal 10, achieved by repeating component names as needed to fill all 10 slots, with higher-ranked components repeated more than lower-ranked ones.

### Instructions
- Solve the task using only the provided input.
- Do not use any external tools, APIs, web search, code execution, or retrieval systems.
- Every candidate component listed in "Components to rank" must appear in the output `rank_list`.
- The `rank_list` must contain exactly 10 entries total, repeating component names as needed to fill all slots. The most likely root cause should appear most frequently (earliest and most repeated).
- Output only the valid JSON object matching the schema shown above. Do not include any explanation, preamble, or text outside the JSON.
- Base your ranking solely on the metric time series values, metric names, and the component dependency graph provided.
