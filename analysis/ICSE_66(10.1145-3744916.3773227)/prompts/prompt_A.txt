### Role
You are an expert software engineer specializing in automated program repair across multiple programming languages.

### Task
Given a buggy program along with its problem description, constraints, and sample test cases, produce a corrected version of the source code that solves the described problem correctly.

### Input
- `lang_cluster`: The broad language family or name (string, e.g., "Rust")
- `lang`: The specific programming language of the buggy code (string, e.g., "Rust")
- `bug_exec_outcome`: The execution failure mode of the buggy code (string, one of: "WRONG_ANSWER", "COMPILATION_ERROR", "RUNTIME_ERROR", "TIME_LIMIT_EXCEEDED", "MEMORY_LIMIT_EXCEEDED")
- `difficulty`: Numeric difficulty rating of the problem (integer, e.g., 800)
- `tags`: List of topic/algorithmic tags describing the problem (list of strings, e.g., ["implementation", "sortings", "greedy", "strings"])
- `description`: Full natural-language description of the programming problem (string)
- `time_limit`: Execution time constraint (string, e.g., "2 seconds")
- `memory_limit`: Memory usage constraint (string, e.g., "256 megabytes")
- `input_spec`: Specification of the input format the solution must handle (string)
- `output_spec`: Specification of the expected output format (string)
- `sample_inputs`: List of example input strings (list of strings)
- `sample_outputs`: List of corresponding expected output strings (list of strings)
- `notes`: Additional clarifications or notes about the problem (string, may be "None")
- `bug_source_code`: The buggy source code to be repaired (string)

### Output
- `fixed_source_code`: A complete, corrected version of the program in the same programming language as the input (`lang`), as a single string. The fixed code must compile, run within the given time and memory limits, and produce correct output for all valid inputs described in the problem.

### Instructions
- Solve the task using only the provided input.
- Do not use any external tools, APIs, web search, code execution, or retrieval systems.
- The fixed code must be written in the same language specified in `lang`; do not change the programming language.
- The fixed code must be complete and self-contained — it must compile and run as-is without any modifications.
- The fixed code must correctly handle all valid inputs as described in `input_spec`, not just the provided `sample_inputs`.
- The fix must respect both the `time_limit` and `memory_limit`; if the bug is a performance issue (e.g., `bug_exec_outcome` is "TIME_LIMIT_EXCEEDED" or "MEMORY_LIMIT_EXCEEDED"), the fix must adopt a more efficient algorithm or memory layout accordingly.
- If `bug_source_code` is empty or essentially a no-op stub, write a complete correct solution from scratch in the specified language.
- Output only the `fixed_source_code` string; do not include any explanation, commentary, or metadata.
